Detection Coverage

What it catches

Each rule targets a specific misconfiguration class with a typed ID, severity rating, and remediation guidance.

Rule ID Severity Target Description
DOCKER-001 HIGH Dockerfile Missing USER directive — container runs as root by default
DOCKER-002 MEDIUM Dockerfile Unpinned base image — latest tag or no tag causes non-reproducible builds
DOCKER-003 CRITICAL Dockerfile Potential secret baked into ENV or ARG instruction
COMPOSE-001 CRITICAL docker-compose Docker socket bind-mounted into container — full host control possible
COMPOSE-002 CRITICAL docker-compose privileged: true grants the container all host kernel capabilities
COMPOSE-003 HIGH docker-compose network_mode: host bypasses Docker's network namespace isolation
Getting Started

Install & run in 3 commands

Requires Go 1.21+. No dependencies to install separately — everything compiles into a single binary.

Build from source
# Clone and build
git clone https://github.com/kushardogra/docker-misconfig-scanner
cd docker-misconfig-scanner
go build ./cmd/scan/
Scan your project
# Scan a directory
./scan ./your-project/

# JSON output for pipelines
./scan ./your-project/ -o json
Origin

Built from a real incident

This tool didn't start as a side project. It started as a post-mortem.

A production environment running Docker with UFW enabled was breached via ransomware. The root cause: Docker manipulates iptables directly, creating its own DOCKER chain that silently bypasses UFW rules entirely. Combined with containers running on default credentials and no USER directive, attackers had full access.

UFW reported all rules as active. No alerts fired. The firewall appeared to be working — it wasn't. This is Docker's default behavior, not a bug, which makes it far more dangerous.

docker-misconfig-scanner was built to catch these conditions statically, before a container ever runs. The tool's detection logic also underpins an ongoing empirical study of misconfiguration prevalence across public GitHub repositories.
